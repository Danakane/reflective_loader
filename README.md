# Linux shared object reflective loader

I made this PoC to experiment with reflective loading of Rust payloads on Linux.

Reflective loading has received considerably less attention on Linux than its Windows counterpart, partly because of the **`memfd_create`** technique, which makes it possible to execute binaries from anonymous in-memory files.

As a result, there are relatively few open-source implementations of reflective loading for Linux. Among the ones I found, none supported **thread-local storage (TLS)**, which is required by more complex payloads such as binaries generated by Rust.

This project explores how to perform reflective loading of shared objects while properly handling TLS initialization.

## Technical solution

The loader parses the ELF file and, when it finds a **`PT_TLS`** program header, allocates a memory block based on the TLS template information contained in the ELF file.

The relocation phase also requires some special handling for TLS-related relocations:

- The **TLS module ID** is patched with the value of the loader's thread ID.
- Instead of resolving TLS-related functions to their libc implementations, the loader redirects them to its own implementations:
  - `tls_get_addr` → `__reflective_tls_get_addr`
  - `__cxa_thread_atexit_impl` → `__reflective_cxa_thread_atexit_impl`

This way, when the payload calls either of these functions, the call is redirected back to the loader, which can then handle the payload's TLS data appropriately.

## Limitations

This codebase is only a PoC to experiment with TLS handling on Linux; it is not a fully functional reflective loader.

Several "shortcuts" used in the code would break if you tried to extract the compiled code and use it as shellcode. Among them:

- Direct references to **`__reflective_tls_get_addr`** and **`__reflective_cxa_thread_atexit_impl`**
- The use of the global variable **`g_runtime`** to keep track of the TLS memory block

Additionally, the current implementation does not support multi-threaded payloads. 
Supporting this would require allocating a new TLS memory block whenever a new thread calls **`__reflective_tls_get_addr`** and keeping track of these blocks using their corresponding thread IDs.

Only support x86_64.

## Compilation

```bash
gcc -fPIC -g reflective_loader.c -o reflective_loader
```

## Usage

```bash
./reflective_loader <PAYLOAD>
```
